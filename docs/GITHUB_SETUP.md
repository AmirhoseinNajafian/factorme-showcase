# GitHub repository setup

Suggested repository metadata:

- **Repository name:** `factorme-showcase`
- **Description:** `A Persian-first invoice workspace for freelancers and small businesses. Product overview, UI previews, brand assets, and project documentation — no application source code.`
- **Visibility:** Public, if the goal is to present the project as a portfolio piece.
- **Default branch:** `main`
- **Website field:** Leave empty until a public FactorMe domain is live.
- **Topics:** `invoice-management`, `invoice-generator`, `persian`, `rtl`, `small-business`, `freelancer-tools`, `saas`, `product-showcase`, `business-tools`, `ui-ux`

## Upload this showcase package

1. Extract the `FactorMe-Showcase.zip` archive on your computer.
2. On GitHub, create a new repository named `factorme-showcase`.
3. Choose Public if you want the portfolio page to be visible to everyone.
4. Do not initialize another README, license, or `.gitignore`; this package already includes the repository files and intentionally does not include an open-source license.
5. Upload the **contents** of the extracted folder to the repository root. Do not upload the ZIP as a nested file.
6. Make sure `README.md`, `README.fa.md`, `assets/`, and `docs/` are visible at the repository root.
7. In the repository's About section, add the suggested description and topics.
8. In **Settings → General → Social preview**, set `assets/brand/social-preview.jpg` as the social preview image.

## Important scope checks before publishing

- Do not add the Local or Hosting application ZIPs to this repository.
- Do not add `node_modules`, `data/db.json`, SQL exports, `config.php`, `.env`, logs, backups, or real customer invoices.
- Keep the repository's purpose as a showcase; it is not an open-source code repository.
- Do not add a license unless you decide what reuse rights you want to grant. Public visibility alone does not make the project open source.
